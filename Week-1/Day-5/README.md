# Day 5 - Git & GitHub Workflow

## What I learned today

Today I learned how Git helps developers manage and track changes in their projects. I understood that Git is not only a tool for saving code, but it helps teams work together, review changes, and keep the project history organized.

## Git Fundamentals

I learned the basic Git workflow and how each step works:

- `git status` helps me check the current state of my project and see changed files.
- `git add` moves changes to the staging area to prepare them for a commit.
- `git commit` saves a snapshot of my changes with a clear message explaining what was done.
- `git push` uploads my commits to GitHub.

I also learned why writing clear commit messages is important because it helps other developers understand the project history.

## Feature Branch Workflow

Today I learned that developers usually don't work directly on the main branch. Instead, they create a feature branch for each task.

The workflow is:

1. Create a new feature branch.
2. Make changes and test them.
3. Commit changes with a meaningful message.
4. Push the branch to GitHub.
5. Open a Pull Request for review.
6. Merge the changes after approval.

This keeps the main branch stable and makes collaboration easier.

## Pull Requests

I learned that a Pull Request is a way to ask the team to review my changes before adding them to the main branch.

A good Pull Request should include:
- A clear title.
- A description explaining what was changed.
- Any important notes for the reviewer.
